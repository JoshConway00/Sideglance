# Sideglance project instructions

Sideglance is a native SwiftUI macOS overlay for local Codex activity. Use [README.md](README.md) for focused feature context and [CONTRIBUTING.md](CONTRIBUTING.md) for contribution boundaries; read only sections relevant to the task.

- Start with Git status and the relevant source. Preserve unrelated work and existing project rules. Carry authorised work through clear completion checks; resolve routine choices locally and identify essential missing inputs or material conflicts.
- Keep one persistent notification with live activity and its coloured indicator inside. Preserve the latest summary while a replacement generates; report outcomes before current/planned actions without inventing completion. Keep original history available.
- The local activity reader is read-only. Keep credentials, task exports, quality logs, user preferences and build products out of Git. Use fictional examples in tests and screenshots. Apple Intelligence is the default; cloud summaries remain opt-in and consume allowance.
- Build and verify code changes with `./build.sh` on Apple Silicon and a macOS 26+ SDK; it builds and runs offline regression tests. Use focused link/content checks for documentation-only changes. Broaden or repeat checks only when changes, failures or unresolved concerns justify it. Compilation does not prove UI behaviour, installation on another Mac or summary accuracy.
- Use bounded independent delegation when it materially helps and the active client permits it. Specify objective, essential context, file ownership and required evidence; continue independent work and integrate findings. Work locally for simple or tightly coupled tasks. Agent consensus is not verification.
- Keep changes focused on a feature branch. Prepare PRs for maintainer review; do not infer authorisation to merge, publish a release, change repository security, send email or modify other projects. Respect explicit user authorisation for those actions. Feature-request email opens a reviewed draft; its Codex route prepares implementation, tests, self-review and a commit without automatically pushing or creating a PR.
- Use relevant available skills without broad keyword triggers or mandatory whole-library reads. This file does not change model, account, global settings or skill precedence. Report changed behaviour, actual verification and remaining limits concisely.

Local setup provenance and rollback, when present: `docs/codex-setup.md` (private, ignored by Git).
